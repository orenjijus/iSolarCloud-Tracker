# Solusi: Data 2025-12-15 Tidak Masuk ke mart_site_performance_daily

## Masalah
Data untuk tanggal 2025-12-15 sudah di-fetch dan masuk ke raw table, tapi tidak muncul di `mart_site_performance_daily`.

## Kemungkinan Penyebab

1. **Incremental Logic**: Model incremental hanya memproses data dengan `date_key > MAX(date_key)`. Jika sudah ada row untuk 2025-12-15 (meskipun NULL), incremental tidak akan memproses ulang.

2. **Data Tidak Masuk ke Layer Intermediate**: Data mungkin tidak mengalir dari staging ke mart layer karena filter incremental di layer intermediate.

3. **MAX Date Key Sudah 2025-12-15 atau Lebih Baru**: Jika MAX(date_key) sudah >= 2025-12-15, incremental filter akan melewatkan data tersebut.

## Langkah Diagnosa

1. **Jalankan query diagnostik**:
   ```bash
   psql -d your_database -f queries/diagnose_2025_12_15_data.sql
   ```

2. **Periksa hasil** untuk melihat di layer mana data berhenti.

## Solusi

### Opsi 1: Re-ingest dengan Variabel dbt (RECOMMENDED)

Gunakan variabel `reingest_start_date` dan `reingest_end_date` untuk memaksa dbt memproses ulang tanggal 2025-12-15:

```bash
cd dbt
dbt run --select mart_site_performance_daily --vars '{"reingest_start_date": "2025-12-15", "reingest_end_date": "2025-12-15"}'
```

Atau untuk memproses semua model yang terpengaruh:

```bash
dbt run --select +mart_site_performance_daily --vars '{"reingest_start_date": "2025-12-15", "reingest_end_date": "2025-12-15"}'
```

### Opsi 2: Re-ingest Semua Layer (Jika Opsi 1 Tidak Berhasil)

Jika data tidak masuk ke layer intermediate, perlu re-ingest dari staging:

```bash
# Re-ingest staging
dbt run --select stg_isolarcloud__perf_unpivoted --vars '{"reingest_start_date": "2025-12-15", "reingest_end_date": "2025-12-15"}'

# Re-ingest mart layers
dbt run --select mart_meter_performance_5min mart_sensor_measurements_5min --vars '{"reingest_start_date": "2025-12-15", "reingest_end_date": "2025-12-15"}'

# Re-ingest sensor daily
dbt run --select mart_sensor_daily --vars '{"reingest_start_date": "2025-12-15", "reingest_end_date": "2025-12-15"}'

# Re-ingest fact calculations
dbt run --select fact_site_calculations_5min --vars '{"reingest_start_date": "2025-12-15", "reingest_end_date": "2025-12-15"}'

# Re-ingest site performance daily
dbt run --select mart_site_performance_daily --vars '{"reingest_start_date": "2025-12-15", "reingest_end_date": "2025-12-15"}'
```

### Opsi 3: Hapus Row yang Salah dan Re-run (Jika Ada Row NULL)

Jika sudah ada row untuk 2025-12-15 dengan nilai NULL, hapus dulu:

```sql
-- Hapus row untuk 2025-12-15 jika ada
DELETE FROM "MMSR"."mart"."mart_site_performance_daily" 
WHERE date_key = '2025-12-15';

-- Kemudian jalankan dbt run normal (tanpa variabel reingest)
dbt run --select mart_site_performance_daily
```

## Verifikasi

Setelah menjalankan solusi, verifikasi dengan:

```sql
SELECT 
    date_key,
    site_name,
    daily_energy_mwh,
    daily_ghi_kwh_m2,
    daily_poa_weighted_kwh_m2,
    availability_percent
FROM "MMSR"."mart"."mart_site_performance_daily"
WHERE date_key = '2025-12-15'
ORDER BY site_name;
```

## Catatan Penting

- Model incremental menggunakan filter `date_key > MAX(date_key)`, jadi jika MAX sudah 2025-12-15, data baru tidak akan diproses.
- Gunakan variabel `reingest_start_date` dan `reingest_end_date` untuk memaksa re-processing tanggal tertentu.
- Pastikan data sudah ada di raw table sebelum menjalankan dbt.
